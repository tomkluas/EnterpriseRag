## 填写模型

在仓库根目录编辑 `v3.local`，不要编辑旧 `.env`，不要在聊天里发送密钥。独立数据库、原件目录和开发令牌已准备好；开发令牌用于工作台登录，只保留在页面内存。

| 配置项 | 填什么 |
| --- | --- |
| `V3_MODEL_BASE_URL` | 回答服务的 OpenAI 兼容地址，通常以 `/v1` 结尾 |
| `V3_CHAT_MODEL` | 服务商实际支持的回答模型名称 |
| `V3_SECRET_MODEL` | 回答服务密钥 |
| `V3_RERANK_BASE_URL` | 精排服务基础地址。当前千问地址可保持与回答服务一致，代码会按模型选择千问原生接口或兼容接口，无需手拼路径 |
| `V3_RERANK_MODEL` | 精排模型名称。精排就是让模型再次比较问题与候选片段，选出更相关的内容 |
| `V3_SECRET_RERANK` | 精排服务密钥；不配置独立地址时使用回答服务密钥 |
| `V3_EMBEDDING_BASE_URL` | Embedding 服务地址；将文字变成便于相似度搜索的数字向量 |
| `V3_EMBEDDING_MODEL` | Embedding 模型名称 |
| `V3_EMBEDDING_DIMENSION` | 该模型的向量维度；当前实际返回并配置为 1024。部署脚本读取此项，不能任意改成其他数值 |
| `V3_SECRET_EMBEDDING` | Embedding 密钥 |

前三项和精排配置由 V3 回答服务读取。Embedding 四项是独立的部署准备资料，需要在 WeKnora 模型管理和 Dify 模型供应商中配置同一真实服务；填写文件不会自动向平台安装插件或创建模型。不要把普通对话模型名称填成精排模型。

修改后重启 V3 API 和 Worker，平台模型配置变更按各平台步骤保存。主进程不会热加载密钥。接入前先验证 `/embeddings`、`/rerank` 和流式 `/chat/completions`，分别记录可用性与回答质量。

## 绑定知识库

1. 平台管理员先创建远端知识库，选定真实 Embedding。Dify 使用高质量索引，另建唯一的字符串元数据字段 `v3_binding_id`。
2. 给机器密钥授权到该远端知识库；WeKnora 按 retrieve／ingest 区分用途。Dify 数据集范围密钥仍可能允许数据集内多种操作，不能据字段名称认定它具备只读能力。
3. V3 管理页“知识底座”填写地址、平台知识库 ID 和 `V3_SECRET_...` 引用。地址填写平台根地址，不加 `/api/v1` 或 `/v1`。实际密钥放在 `v3.local`。
4. 用真实配置完成 G0、签收报告，再准备知识库切换。页面登记不等于启用。当前两个实例均不具备生产准入资格。

同一实例绑定一个预建物理知识库；需要独立模型或安全范围时另登记实例。重复文件去重、同一原件的重建代次必须完成 G0 验证；不能手工复用已绑定到其他业务版本的远端文档。重建到新物理库时先由管理员准备新库及受限凭据。

## 当前平台问题

Dify Agent 启动配置已在本机隔离部署中修正：`envs/core-services/dify-agent.env` 中未启用追踪时应省略 `DIFY_AGENT_TRAJECTORY_OTLP_TRACES_ENDPOINT`，不能赋空字符串，否则 1.18.0 镜像的 URL 校验会使容器循环重启。当前知识库测试实例未部署 `local_sandbox`，因此在 `isolation.override.yaml` 的 `agent_backend.environment` 中显式设置 `DIFY_AGENT_LOCAL_SANDBOX_ENDPOINT: ""`，使用镜像支持的无执行沙箱模式；需要 Agent 执行命令时，必须另行部署沙箱并为双方配置一致的认证令牌，不能仅填写沙箱地址。上述文件位于本机临时部署目录，重建测试环境时需保留这些调整。修正后 Agent OpenAPI 和 Dify API 健康接口均返回 HTTP 200；这不代表完整 Agent 工作流或真实模型质量已验收。

WeKnora v0.9.0 默认 ParadeDB 组合中，关闭问题生成时的部分授权过滤 SQL 返回 500。开启问题生成的对照实例通过了受限召回诊断，但尚不能把这个开关视为生产修复，真实模型、生成问题子块等仍需验收。

Dify 1.18.0 原始镜像文件 API 载入资料创建者后未设置当前租户，导致上传断言失败。`deploy/v3/dify-compat` 提供固定基础 digest 的最小兼容镜像：使用平台自己的成员关系查询补齐租户上下文，保留原范围校验。只有隔离 Dify 项目启用了它，V3 默认部署不会自动替换平台镜像。补丁改变了构建产物，必须记录补丁及镜像 ID，并重新完成 G0。恢复官方镜像只需移除测试项目的 `tenant-compat.override.yaml`，不删除数据卷。

原始故障与补丁诊断分别记录在 `docs/testing/v3`，保留为历史证据。最新本机部署已使用真实云端模型：WeKnora 开启问题生成后，受限向量／关键词／混合召回通过；Dify 兼容镜像的高质量索引及受限语义／全文召回通过。该特定配置允许 development 文档试运行，不能据此认定官方原始镜像的故障已修复或完整生产验收通过。
