# 工作台问题修正

本次沿用 Vue 3、FastAPI、SQLAlchemy 和 PostgreSQL，不引入新的身份服务或界面组件库。

## 实施范围

- 数据库：为所有业务表和字段补充中文备注。显式迁移同时更新已有 PostgreSQL 表，重复运行安全。
- 成员：保留企业令牌登录，增加账号密码登录。管理员创建/重置密码；密码使用带随机盐的 scrypt 摘要，登录凭据独立存储且不通过成员接口输出。会话仅保存令牌摘要，8 小时有效；重置密码、停用及退出使会话失效；失败登录限速。
- 权限：资料维护人员从当前租户成员与用户组选取允许/禁止对象；保留已有规则，明确空允许列表继承知识库规则、禁止优先。
- 问答：按消息持久化 Trace，展示改写、检索、精排、生成和整体耗时、结果；仅会话本人可查看，不记录模型密钥或未经授权的资料内容。
- 角色：现有 reader/editor/admin 固定三种，不新增自定义角色系统；在界面说明职责及资料权限独立性。
- 交互：统一使用可键盘操作的应用内对话框，替换撤回、授权、反馈弹框；知识底座以当前配置、切换流程、服务清单组织，登记放入弹框。

## 验证顺序

1. 先补充并运行登录/会话撤销、授权对象访问控制、Trace 所有权与元数据备注的失败用例。
2. 实施后运行相关后端测试及身份、问答、恢复回归；执行前端测试与构建。
3. 启动隔离的本机测试服务，在浏览器验证登录、成员密码、权限对话框、Trace 和底座页面；检查桌面和窄屏布局。
4. 因涉及身份和权限，独立评审限定于认证、授权及 Trace 数据访问，不扩展需求。

不修改用户已有 README、启动脚本改动。本机启用前确认没有运行中的任务，再应用迁移并通过现有脚本重启；验收使用临时资料，不创建真实业务测试记录。

## 使用方式

1. 现有管理员在登录页选择“企业令牌”，继续使用原启动令牌登录。也可以在成员页编辑自己的账号设置密码；保存后重新用账号密码登录。
2. 在“成员与权限”新增成员，填写账号、角色和至少 12 位初始密码。账号、密码与登录页地址由管理员交给成员，不自动发送消息。
3. 在“知识资料 → 访问权限”勾选允许或禁止的成员/用户组。资料需要发布，普通成员才能在知识库中看到并提问。授权完成后，成员可刷新可用知识库。
4. 每次回答下方的“处理明细 / Trace”展示实际执行的阶段、耗时、结果与安全处理过的失败原因。历史回答不补生成明细；不会展示模型密钥或完整模型请求。
5. 当前系统角色固定为知识使用者、资料管理员、系统管理员，本次未扩展自定义角色。用户组可用于批量授予资料访问权。

本机已执行 `app.v3.cli --env-file v3.local migrate`，并使用 `tools/v3/start_local.ps1 -Restart` 重新启动 API/Worker。容器或其他环境部署时也应先执行显式迁移，再启动新版服务。
