# 原件孤立对象回收

此工具只回收没有任何业务版本引用的原件对象，不用于删除历史版本、撤回资料、备份或审计。默认为盘点；执行必须提供已保存清单及显式删除参数。

在仓库根目录 PowerShell：

```powershell
$env:PYTHONPATH = 'backend'
backend/.venv-v3/Scripts/python.exe -m app.v3.cli --env-file v3.local plan-orphan-gc --retention-days 7 --output <不存在的盘点文件路径>
backend/.venv-v3/Scripts/python.exe -m app.v3.cli --env-file v3.local apply-orphan-gc --plan <已核对盘点文件> --confirm-delete
```

配置与权限：仅管理员；限当前企业 `SHA256(tenant_id)/32位版本编号` 命名空间。保留期至少一天，默认七天；这里的保留期只约束真正孤立对象，不是企业历史文档和备份的保留政策。盘点文件不能覆盖已有文件，包含对象编号、hash及修改时间，不包含原文。不要改写清单绕过检查；修改、超过24小时、目录修订变化、对象变化或新引用都会阻止执行。

执行前持久化 maintenance 状态的 `orphan_gc` 任务意图；在企业独占协调锁下再核对全部版本引用、hash、大小和时间，避免与上传同时执行时误删。实际删除保存逐件回执及审计，失败返回非零状态。进程崩溃后可按任务意图和原清单核对，不能点普通任务重试；普通Worker不领取maintenance任务。已经不存在的对象单独记录，不再次删除。数据库和文件系统不具备共同事务，强制终止可能留下待人工核对的意图，不能把无回执当作一定未删除。

本地文件拒绝软链接、Windows重解析点及越界路径。S3只支持无版本化桶，盘点和执行两个阶段都重新检查版本化配置。执行前会在配置前缀的 `__orphan_gc_canary__/随机编号` 创建一个合成探测对象：错误IfMatch必须返回412且原文保持一致，正确IfMatch删除后必须HEAD为404；任一步失败，均不会删除回收候选。管理员凭据需要该探测前缀的PUT/GET/HEAD/DELETE权限。盘点仍只读。

候选条件DELETE必须带IfMatch，不能退回无条件删除，随后HEAD确认当前对象不存在。探测结果不明时也不使用无条件清理，错误信息提供可能残留的合成对象编号供核对。LIST与HEAD时间允许同秒精度差异，保留期使用两次观测中的较晚时间，hash、大小及ETag仍严格核对。旧版本和备份清理需要另外制定策略；执行期间桶管理员不得改变版本化设置。

验证：临时本地文件测试、S3 Stubber成功/412冲突/版本化拒绝及探测失败测试已执行。真实隔离MinIO服务忽略DELETE IfMatch，整体兼容性未通过；新保护成功拒绝回收，候选DELETE数为0。报告见 [真实S3验证](../testing/v3/real-s3-2026-10-31.md)。尚未在企业目标S3桶验收，本轮未对现有业务原件执行回收。生产使用前应先在同配置的隔离桶完成真实协议验收，并由运维确定保留期限。
