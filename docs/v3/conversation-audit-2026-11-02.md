# 按会话展示问答审计

目标：审计列表以会话为单位，同一会话的多轮问答按时间顺序查看，每轮保留证据、处理明细和反馈。

实现范围：复用 Conversation/Message，不迁移数据库。保留原按消息查询接口，新增 `/api/v3/admin/trace-conversations` 列表和 `/{conversation_id}` 详情接口，页面默认使用会话列表。仅前端归组会造成同一会话被消息分页拆散，因此在数据库查询中先筛选会话、再分页。无需增加视图切换或另一套页面。

筛选规则：关键词、成员、消息状态和时间按消息匹配；任一消息命中即选中所属会话。会话行和汇总统计展示选中会话的全部问答，并单独返回命中消息数。详情不沿用消息筛选，保留上下文，按时间和消息标识升序分页。列表按最近活动时间和会话标识降序。空会话不进入审计。会话标题优先用已有自定义标题，默认标题用第一轮问题替代。

权限：所有查询要求 `traces.view`；消息与会话必须同时匹配租户及所有者，详情仅白名单输出字段，查看当前消息页的行为逐条写 `trace.view` 审计。禁止越租户读取，停用角色后立即拒绝。

实施顺序：

1. 补充真实临时数据库测试，覆盖分组分页、筛选保留上下文、同时间排序、租户/成员隔离、字段白名单、审计及 HTTP 路由。
2. 复用现有消息详情字段筛选，增加会话列表与分页详情查询，注册管理路由。
3. 调整现有 Vue 审计页面，列表按会话展示，详情按问答轮次展开并独立分页，保持当前配色和模态交互。
4. 运行定向后端测试、前端测试与构建，核对页面实际交互。

验证结果：会话/消息审计 12 项、API 7 项、工作台 16 项测试通过；前端 3 项测试和生产构建通过。使用临时 SQLite 与 23 轮模拟会话完成浏览器检查，覆盖关键词命中追问后保留首问、来源展开、消息分页、翻页回到首轮、关闭后焦点恢复，以及 390px 窄屏详情。未在本次验证中连接真实 PostgreSQL 或读取实际业务会话。
