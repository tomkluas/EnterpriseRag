# 企业管理与资料工作台改造

目标：把租户、组织、成员、角色、资料授权与问答审计连成可管理、可测试的完整流程。

## 统一规则

- 租户是公司边界；组织是租户内的部门树；成员属于一个部门并可分配多个角色。部门不隐式授予资料访问权。
- 自定义角色包含系统操作权限；资料阅读规则只引用角色，支持继承知识库默认角色后追加资料角色、单独授权和明确禁止。禁止优先。角色停用、成员停用及授权变化必须触发权限修订，历史问答与正在输出的回答沿用现有重新校验链路。
- 保留三个内置角色作为默认配置，支持新增业务角色。内置管理员不可删除，防止移除最后一个有效管理员。
- 旧成员/用户组授权迁移为专门的兼容角色，并迁移对应成员关系，不将个人授权变成全员授权。旧字段只用于兼容导入，不出现在新管理界面。
- 管理员的问答审计权限单独控制，仅可查看本租户。列表分页，按成员、问题、时间、状态筛选；详情包含问题、回答、反馈、来源与阶段耗时。查看详情写审计记录，不返回模型密钥。
- 知识资料页采用知识库列表、可筛选资料表、资料详情与版本面板；新建知识库、上传、新版本和角色授权有独立入口。

## 实施与验收

1. 后端：组织树、角色/成员关系、租户状态、资料角色规则、旧授权迁移；补反例测试验证越租户、越权、角色停用、组织循环和最后管理员保护。
2. 前端：独立资料工作台、组织成员角色管理、管理员问答审计页面；按后端权限展示入口，后端独立校验权限。
3. 认证：租户登录上下文由受验证的会话或身份令牌决定，不信任普通请求传入的租户编号。
4. 迁移/恢复：显式增量迁移、中文备注、旧备份兼容、重复迁移不重复创建角色或扩大访问范围。
5. 验证：定向与相关回归、PostgreSQL 隔离迁移、浏览器实际操作与独立权限评审；确认任务队列安全后启用本机版本。

用户已确认：本次仅管理当前公司，不提供平台级租户管理。认证仍使用服务配置的租户，企业信息可编辑、租户标识只读。其他实现选择由代理按上述边界完成，不增加设计审批关卡。

## 管理员操作顺序

1. 在“企业与权限 → 企业信息”填写公司名称；公司根部门名称同步更新。
2. 在“组织架构”建立部门树。成员属于一个部门；原有多个用户组迁移时，第一个组成为主要部门，其余旧阅读范围由历史兼容角色保留。
3. 在“角色”创建业务角色，选择系统操作权限。阅读资料需要“阅读知识资料”；维护知识库、管理成员和问答审计分别授予，不依赖固定角色名称。
4. 在“成员”选择部门、分配一个或多个角色，设置初始密码。部门上下级不会自动授予资料权限。
5. 在“知识资料”选择知识库，配置“默认角色授权”。资料可继承默认允许角色并追加自己的角色，也可单独设置；知识库和资料的明确禁止始终优先。资料处理完成并发布后，获得角色授权的成员才能使用。
6. 在“问答审计”按问题、账号、时间和状态查询，查看回答、反馈、来源与 Trace。此权限允许查看本公司所有问答结果，应只授予负责审计的人员；每次查看详情都会记录操作审计。

历史兼容角色用于保持旧访问范围，不等同于恢复直接给人员授权的界面。管理员可逐步将历史角色替换为清晰的业务角色，再解除旧关联。

## 本机启用结果

2026-11-02 已完成显式迁移并重启 API/Worker。提交迁移前逐对比较了现有 8 组“成员—资料”访问结果，范围一致；校验失败会使迁移事务回滚。实际数据库现为 21 张业务表、157 个有备注字段。原有 3 个失败任务与 5 个完成任务保留，未重试旧失败任务。
