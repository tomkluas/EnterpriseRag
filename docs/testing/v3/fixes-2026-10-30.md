# V3 任务租约与失败草稿修复验证

日期：2026-10-30。结论：上一轮复查的两个缺陷已修复，相关反例与回归通过。完整企业生产验收仍未完成；本报告不改变本机 development 资格的边界。

## 修复内容

1. Worker 同时监控业务处理与心跳。心跳因租约失效失败时取消当前处理，回收两个异步任务，异常进入原有处理边界，不再从 finally 逃出终止循环。失效租约仍禁止写回，上传结果不明时仍由 submitting 状态阻止重复上传，不能用放宽租约来恢复处理。
2. 耗尽重试的未就绪草稿记录为 failed。知识资料页为有失败任务的未发布版本显示“取消失败草稿”。取消保留原件、已发布版本和审计，标记对应待执行／失败任务为 cancelled；取消版本不能发布、重试或进入后续切换清单。
3. 取消在数据库事务内检查维护权限、版本归属、发布状态、正在运行的任务及未知远端结果，并锁定对应任务行，避免与后台领取竞争。正在处理、待人工对账或 submitting 的版本明确拒绝取消。
4. 取消递增资料目录修订号，使原切换准备结果失效，管理员须重新准备目标索引。正常未取消草稿仍参与同步，未放宽目标全部就绪要求。

API：`POST /api/v3/documents/{document_id}/versions/{version_id}/cancel`。此操作是停止使用失败草稿，不表示远端索引／原件已经物理删除。原件仍可由资料维护人员下载，未知上传结果仍需先对账。
