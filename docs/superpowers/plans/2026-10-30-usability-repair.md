# 可用性排障与修复

目标：修复对话等待不结束，验证现有主要入口在成功、失败和并发请求下的行为。沿用当前工作区的未提交版本，不恢复已删除文件，不更改用户密钥、账号或现有知识库。

1. 已复现：纯模型 2.2 秒完成；知识库对话超过 45 秒无输出，健康检查同时阻塞；线程堆栈停在同步 Embedding TCP 连接。
2. 先补回归测试：慢 Embedding 不阻塞事件循环；检索失败可见；SSE 连接/读取超时、断流、停止；会话切换不丢消息；禁用检索确实生效。
3. 修复检索链路：异步 HTTP，有界连接与读取超时，Chroma 操作移至线程；错误写日志并经 SSE 告知；数据库和 Tavily 同步 I/O 同样隔离。保持 SQLAlchemy session 不被并行跨线程使用。
4. 修复流生命周期：立即返回状态，检索与模型调用设置时限，断开时取消后台任务；前端处理超时、非正常 EOF，隔离旧请求回调及会话。
5. 全局检查：鉴权/配置/知识库增删上传/检索/模型测试/前端构建。自动化测试使用临时配置和数据；真实服务检查复用现有配置，测试产生的数据清理。
6. 交付：重启更新后的服务，运行实际对话和并发健康检查；报告已验证能力及外部依赖的实质限制。
