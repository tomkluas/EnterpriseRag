# 生产补齐：未知上传结果对账

沿用现有 V3 设计、当前分支和用户继续实施授权。先交付可审计的人工回执签收，不把人工证据当成自动证明，不开放“未找到就重新上传”。自动发现、删除确认、容量、完整恢复和业务质量仍为后续任务。

## 契约

- 管理 CLI 只读导出待对账任务快照；签收 JSON 必须精确匹配租约、版本、原件 SHA256、绑定、实例及集合。
- 管理员提供远端 ID、批次、核对说明和证据文件 SHA256。签收保存在任务 payload，审计记录操作者。拒绝跨绑定重复远端 ID、过期快照和非未知任务。
- 事务内锁任务；只恢复状态轮询，不再次上传、不直接 ready 或发布。恢复任务固定原底座，避免期间切换导致误用回执。
- 已撤回资料的迟到回执只进入清理队列；不能恢复检索权限。

## 实施顺序

1. 新增隔离数据库测试：正常恢复不重复上传；过期/越权/错误校验/重复绑定拒绝；撤回后只清理。先运行得到失败证据。
2. 实现 Domain 快照与签收、CLI 入口。无需更改数据库 schema。
3. 执行相关回归，更新操作说明及真实验证结果。生产资格保持未通过。

## 验证重点

所有外部证据由有权限运维人员独立核对；工具只能验证内部一致性。不得把其他版本远端 ID 复制到当前绑定。不得在报告写入正文或密钥。测试仅使用临时库与外部服务替身。

## 执行记录

三项实施步骤已完成；业务实现通过 66 项后端回归（含真实 PostgreSQL、0 跳过），随后按独立审查建议补充路由变化测试，对账模块 7 项通过。独立审查未发现已证实阻断问题。未提交、部署或扩大生产资格。人工签收只适用于可唯一确定且无回执的 submitting 绑定，其余状态不猜测、不强制恢复。
