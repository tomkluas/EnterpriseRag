# 生产准入补齐

沿用用户“全部补齐，按生产可用”授权，使用现有分支和未提交工作区。依据 design.md / validation.md / production-readiness.md。企业身份、代表性资料和目标规模之前答复待定，继续保留为真实验收输入，不补造业务签收。此次并行推进可独立实现的缺口，再统一回归和独立评审。

## 任务与文件边界

1. 自动对账：知识适配器、worker、domain中的对账方法及专属测试。先查固定版本本地上游源码。仅接受本次绑定可验证的唯一远端候选，不根据同名旧资料猜测。不匹配、结果为空或冲突保持冻结；绝不以未找到为理由盲目重传。新写入必须保存可验证绑定标识，旧任务无证据保持人工。
2. 监控：models/db的Job创建时间和WorkerPulse迁移、operations和独立monitoring模块、必要chat计时。提供准确积压年龄、空闲Worker心跳、重启后仍可见的聚合指标；告警发送先用本机合成接收器，不擅自联系真实人员。调用链接入由主代理统一。
3. 恢复：recovery模块扩展独立空S3前缀的安全恢复，失败留下隔离清单，不删除不属于本轮的对象。目标原件可核验；恢复仍撤销旧租约与底座资格，不假装底座备份已恢复。专属测试及可复用部署操作。
4. 原件孤立回收：主代理实现两阶段盘点和执行，仅限定单租户对象命名空间；执行时再次核对版本引用、对象hash/年龄、目录修订，默认盘点。业务引用对象、活跃上传、保留期内对象、符号链接和跨租户对象不可删。配置默认不自动运行，不对当前真实原件执行回收。

各任务先失败测试后实现，生产外部能力依赖固定版本源码/真实探针。统一执行隔离PostgreSQL回归、本机服务重载和只读核验。复杂解析、完整两平台灾备、真实企业SSO、业务评分、容量持续测试与签收逐项登记，不以基础工具通过关闭这些项目。

## 执行结果

四项实现已集成。新增生产配置门禁、候选容器构建/非root检查、本机告警真实HTTP送达。独立评审发现流式ContextVar跨Task P1；真实压测发现慢响应头仍持授权锁；原件探针发现Dify相对URL误判，均先复现再修。透明自动重发旧上下文的风险也以失败反例保护。

真实容量预检未通过，单并发也因云Embedding连接超时而失败，未提高预算或换模型。自动对账两底座已找回回执，但索引未ready。真实S3服务缺条件，未用协议替身替代。完整生产目标未完成，证据与剩余项保持在production-readiness.md中。
