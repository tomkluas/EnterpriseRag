# V3 生产能力补齐实施计划

依据 docs/v3/design.md、validation.md、operations.md，以及用户继续补齐授权。在当前分支继续，不提交或覆盖已有工作区。企业身份、真实业务样本和目标规模用户答复“待定”，对应验收必须保留未完成。

## 工作与边界

1. 删除与恢复（主代理）：Worker 的 delete_requested 改为持续确认流程，平台资源不存在后单独记录可见性清理，不声称备份／底层存储已物理抹除。删除和已知回执后的 GET 超时应可重试，不因只读超时进入永久人工对账。以隔离数据库及 HTTP 替身验证。
2. 问答（独立代理）：chat/service.py、chat/models.py 及专属测试。Dify 长问先生成 <=250 字符的检索问，原问题用于回答与持久化；历史使用前保持重新鉴权。生成派发前目录／路由变化只重新检索一次，权限变化立即失败；已输出后不混证据。新增失败测试后实现并验证。
3. 验收工具（独立代理）：新建可独立运行的 tools/v3/acceptance.py 和对应测试。提供 SSE 流式容量检查与冻结业务题评分汇总，排除心跳／状态作为首字，不把错误算正确拒答；记录超时、P50/P95、样本与实际持续时间，生产门槛未满足不能判通过。仅运行本机合成测试，不自行导入业务文档或更改生产数据。

每个代理只改负责文件，不共享业务状态。所有新增行为先失败后实现；统一执行后端回归及必要构建；独立检查本轮跨模块修改。真实完整 G0、S3/平台恢复、企业身份和业务效果的缺证据项不得随单元测试变绿而关闭。

## 删除验证重点

- 首次接受删除不等于资源不可见；确认必须通过对应集合的 GET／404，401、403、5xx 均不能作为已删除。
- 删除任务延迟重排不阻塞其他任务，超时重试不重复发布或开放撤回资料。
- 未知上传及迟到回执不能漏清理；租约失效不得更新副本状态。
- 原件不在本轮自动删除，避免破坏历史、保留和恢复依据。物理保留期限尚未明确。
